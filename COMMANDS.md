# Yana AI — Command Reference

Every command the `yana-ai` CLI (and its `yana` alias) understands, in one
place. This catalogs the CLI binary itself — the same commands you get from
`yana-ai help` — not the 170 Claude Code slash commands under
`core/commands/` (those run inside a Claude Code session, e.g. `/plan` or
`/code-review`, and are a separate, editor-side catalog with no single
reference file of their own yet).

Generated by reading `bin/yana`'s dispatch table and `src/main.rs`'s clap
definitions directly, so it stays accurate to what actually ships — not
aspirational copy. If a command below stops working, that's a real bug:
please open an issue.

Run `yana-ai <command> --help` (where supported) or `yana-ai help` for the
built-in short version of this list.

## Getting started

| Command | What it does |
|---|---|
| `yana-ai` (no args) | Prints the welcome banner — version, live stats, git branch, tips |
| `yana-ai init [target]` | Interactive setup wizard (pick engine, profile, guards) |
| `yana-ai install [target] [--engine all\|claude\|codex]` | Install shared capability surfaces; defaults to Claude + Codex and requires no npm |
| `yana-ai doctor [target]` | Check environment health before starting an agent session |
| `yana-ai doctor --fix` | Same, plus fix suggestions for WARN/FAIL items |
| `yana-ai doctor dispatch [target]` | Cross-check `src/main.rs`'s Commands enum against `bin/yana`'s own dispatch table (catches drift like a command existing in one but not the other) |
| `yana-ai verify [target]` | Verify all safety hooks are wired and active |
| `yana-ai upgrade` | Self-update yana-ai to the latest release |
| `yana-ai version` | Print version |
| `yana-ai banner` | Print the welcome banner only (no command list) |
| `yana-ai help` | Show the full built-in help |

## Chat REPL — usage

`yana-ai chat` is pure conversation — send text, get streamed text back. No
tool-calling, no file edits, no shell execution: it runs as its own process
outside any agent session, so Yana AI's hook system has nothing to intercept
here (the same reason it can't see you running `curl` by hand).

| Provider | Flag | Needs | Default model |
|---|---|---|---|
| Anthropic (Claude) | `--provider anthropic` | `ANTHROPIC_API_KEY` | `claude-sonnet-4-6` |
| OpenAI | `--provider openai` | `OPENAI_API_KEY` | `gpt-4o-mini` |
| Kimi (Moonshot AI) | `--provider kimi` | `MOONSHOT_API_KEY` | `kimi-k3` |
| Ollama (local) | `--provider ollama` | nothing — but `ollama serve` must be running on `127.0.0.1:11434` | `llama3.2` |

With no `--provider` flag it auto-detects, in order: `ANTHROPIC_API_KEY` set →
Anthropic, else `OPENAI_API_KEY` set → OpenAI, else falls back to local Ollama
(no key needed, but nothing stops it from trying even if the daemon isn't
actually running — that surfaces as a connection error on your first message,
not a selection error up front).

```bash
yana-ai chat                                        # auto-detect provider
yana-ai chat --provider ollama                       # force local, keyless
yana-ai chat --provider anthropic --model claude-sonnet-4-6
yana-ai chat --resume <session-id>                   # continue a saved conversation
yana-ai chat --system "You are a terse code reviewer" --verbose
```

A missing key for a cloud provider prints the exact env var to export and
exits immediately — it never silently falls back to a different provider
mid-session.

## Multi-agent launcher (`core/scripts/multi-agent-launch.sh`)

Not part of the `yana-ai` binary's own dispatch table, but shipped alongside it —
see [the full CLI reference](docs/reference/cli-reference.md#multi-agent-launcher)
for the complete walkthrough.

| Command | What it does |
|---|---|
| `multi-agent-launch.sh start --tasks-file <file> --concurrency <n>` | Start multiple agents from a task list |
| `multi-agent-launch.sh status` | Show state per agent — `working` / `blocked` / `done` / `failed` / `unknown` / `killed` |
| `multi-agent-launch.sh log <agent>` | Tail one agent's log |
| `multi-agent-launch.sh kill <agent>` | Stop one agent |
| `multi-agent-launch.sh kill all` | Stop every agent immediately |

## Notes

- Flags like `--json`, `--no-color`, and `--quiet` are supported across most
  read-oriented commands (`doctor`, `audit`, `router suggest`, etc.) — run
  `yana-ai help` for the exact flag table per command.
- Commands routed through Python (`policy`, `guard`, `router`, `rule import`,
  `report html/pdf`) require `python3` on PATH; everything else is native Rust
  via `yana-rt`.
- This file is hand-curated against the actual source (`bin/yana`,
  `src/main.rs`, and each subcommand's own `*Action` enum) as of this
  writing. If Yana AI grows a new top-level command, add it here in the same
  pass — see `bin/yana`'s `usage()` function, which should always list the
  same commands as this file.
