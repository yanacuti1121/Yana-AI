사용자 인터페이스

Yana를 사용하는 네 가지 방법.

각 인터페이스가 제공하는 권한 범위는 다릅니다. 모든 화면이 같은 권한을 갖는 것은 아닙니다.

데스크톱

Yana Studio 1.5

Electron 앱으로 대화, 코드 편집기, 실제 터미널 (PTY), Git, 모델 관리, 권한과 실험 단계의 Design Canvas를 제공합니다.

렌더러 (React/TS) 호스트 (Electron 메인) yana-rt 바이너리 실행

CLI

런타임 CLI (yana-rt)

다음 명령으로 설치하는 Rust 바이너리입니다: cargo install yana-rt. Studio와 같은 TurnEngine과 권한 체인을 사용합니다.

cargo install yana-rt yana-rt chat

물리적 AI

Yana Wheelbot

펌웨어를 갖춘 ESP32-S3 로봇 프로젝트입니다. 별도의 WebSocket/MCP 기기 브리지를 사용하며 같은 TurnEngine을 거치는 전체 경로는 아직 검증되지 않았습니다.

ESP32-S3 펌웨어 ● 있음 브리지 ◐ 개발 중

웹

이 웹사이트

정적 HTML, 프레임워크 없음. 다운로드 페이지는 GitHub Releases API를 직접 호출합니다 — Yana 서버가 중간에 끼어들지 않습니다.

docs/*.html assets/ecosystem-pages.js GitHub Releases API

공유하는 계층

서로 다른 네 개의 구현이 아닙니다.
하나의 제어 계층, 네 가지 진입점.

플랫폼

모델 및 제공자

런타임 카탈로그는 제공자 중립적인 디자인으로 클라우드 및 로컬 서비스를 지원합니다. 정확한 숫자는 버전에 따라 변경됩니다.

플랫폼

에이전트 및 스킬

에이전트는 작업에 따라 배정되며 스킬은 사용 조건이 맞을 때 적용됩니다. 카탈로그는 계속 발전합니다.

플랫폼

커넥터

Google, GitHub, Slack 및 Notion 연결은 각각 별도의 권한과 인증 정보를 가지고 있습니다.

신뢰

증거 및 감사

해시로 연결된 감사 로그와 증거 엔진이 결과를 실제 변경 비교, 테스트와 빌드에 연결합니다.

신뢰

안전 장치

파괴적 작업 차단, 영향 범위 검사, 서킷 브레이커와 감독자의 HALT.

개발자

전체 아키텍처

사용자 인터페이스에서 감독자와 제어 계층, TurnEngine을 거쳐 실행 근거까지 이어지는 구조를 살펴보세요.

Yana 원칙

네 가지 인터페이스. 하나의 규칙.

모델과 인터페이스는 바뀔 수 있어도 권한 체인, 증거와 기능 명세의 경계는 유지됩니다.

감사의 말

Yana AI는 Apache 2.0, MIT 및 기타 허용 라이선스 하에 라이선스된 프로젝트를 포함하여 오픈소스 커뮤니티의 아이디어, 패턴 및 도구를 기반으로 구축되었습니다. 모든 제3자 소스는 각 라이선스에 따라 준수하여 사용됩니다. 이 프로젝트는 개인이나 조직의 지적 재산권을 복사, 오해하거나 침해할 의도가 없습니다. 특정 프로젝트가 디자인 결정에 직접적인 영향을 미친 경우, 관련 소스 파일 및 규칙 문서에 출처가 명시됩니다.
