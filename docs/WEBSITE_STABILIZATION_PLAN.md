# Yana website stabilization plan

This pass preserves the existing multipage static site and its verified product copy. It does not introduce a new framework or a cloud account product.

## Shared files

- `assets/sakura-site.css`: normalize the Yana color, type, spacing, radius, density, diagram, legal, navigation, footer, and motion systems.
- `assets/sakura-site.js`: keep one localized navigation/footer source, scope petals by page mode, remove global cloud-account implications, and expose only one Support & Contact destination.

## Structural pages

- `index.html` / `en.html`: replace the generic orb with the verified Yana Control Field, add the real control-plane story, authority flow, published-product boundaries, and honest status language.
- `support.html`: merge support and official contact information into one task-oriented page.
- `contact.html`: compatibility redirect to `support.html` so old links do not break.
- `wheelbot.html`: replace the decorative robot drawing with verified hardware/protocol/status content from the supplied Wheelbot source.
- `legal-notices.html`, `privacy.html`, `acknowledgements.html`: documentation density, reduced petals, and stable reading width.

## Styling-only or shared-system pages

Architecture, governance, runtime, models, connectors, missions, continuity, evidence, agents/skills, Studio, download and installer pages inherit the normalized technical/product modes first; copy changes are limited to claims verified in repository documentation.

## Verified architecture visuals

- Control Field: provider/model proposals converge on the Yana control plane before files, Git, terminal, apps or devices.
- Authority Stack: Human → Giám Thị → Yana control plane → RuntimeAuthority / TurnEngine → canonical capability → bounded executor → host.
- Execution Rail: Proposal → Decision → Execution → Evidence/Receipt.
- Connector Triad: local Studio profile ≠ optional sign-in identity ≠ service OAuth connector.

## Token changes

Use the supplied Yana tokens as the source of truth: warm canvas `#FBF6F1`, raised white, principle navy, ink `#211A22`, Yana pink `#AE3457`, semantic allow/ask/deny colors, Fraunces/Iowan-style editorial display, Inter/system sans, JetBrains/SF Mono system text, 3/16/999px radius roles, and four deliberate page densities.
