YANA RUNTIME

The engine underneath Yana

yana-rt is the canonical Rust TurnEngine — one bounded provider/tool loop that every Yana surface (Terminal, Desktop, packaged Web) runs on. It doesn't decide what's allowed; that's Governance's job. It decides how a turn actually executes.

How a turn runs

Every model turn — local or cloud — follows the same path. No client gets a shortcut.

TurnRequestClient-neutral: Terminal, Desktop, and packaged Web all submit the same typed request.
↓
Authority preflightFail-closed check before the provider is ever invoked — see Governance.
↓
Provider / tool loopBounded loop over the model plane and the capability plane, streaming typed RuntimeEvents back.
↓
Read-only capabilityRuns canonically, no pause.
Mutating capabilityPauses for human approval — never silently promoted to allowed.

Note: Electron Desktop and packaged Web run this same engine headless — no mutation capabilities are exposed there today, because there is no trusted remote approval-continuation protocol yet. Interactive Terminal is the only path that can approve a mutating call right now.

Install

The runtime ships independently from the Governance layer — its own crate, its own version.

# crates.io
cargo install yana-rt

# verify
yana-rt --version

To govern a repo (rules, hooks, agents) instead of just running the engine, see pip install yana-ai on the homepage's Ecosystem section.
