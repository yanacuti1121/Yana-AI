스택

모델은 교체 가능한 구성 요소 중 하나입니다.

권한과 시스템 상태는 모델 밖에 있으므로 제공자나 에이전트를 바꿔도 권한 경계는 유지됩니다.

지능 계층

로컬 및 클라우드 모델 제공자는 하나의 권한 모델을 공유합니다. 다만 새로운 제공자 게이트웨이가 아직 모든 호출의 처리 경로는 아닙니다.

OpenAI · Anthropic Groq · Gemini Ollama · 로컬

실행 계층

Rust TurnEngine은 형식이 정의된 턴, 스트리밍, 취소와 표준 기능 호출을 관리합니다.

작업 턴 → 스트리밍 → 도구 호출 루프 → 취소 → 부분 출력

권한 계층

감독자(Giám Thị), YanaAuthorityChain, 승인, 범위가 정해진 권한 부여와 HALT가 모델의 추론 밖에서 권한을 유지합니다.

사람 ↓ 감독자 ↓ Yana 제어 계층

시스템 지도

하나의 제어 계층.
인터페이스마다 권한 범위는 다릅니다.

최종 결정권은 사람에게 있습니다. 감독자는 최상위 안전 권한을 가지며, 검토되지 않은 변경을 감지하면 세션 전체를 HALT할 수 있습니다. Studio와 Runtime CLI는 같은 Yana 제어 계층을 거쳐 Rust TurnEngine으로 연결됩니다 (yana-rt). Wheelbot은 별도의 WebSocket/MCP 기기 브리지를 가진 하드웨어 프로젝트입니다. 같은 TurnEngine 경로를 처음부터 끝까지 거친다고 주장하지 않습니다.

인터페이스 경계

모든 인터페이스는 서로 다른 수준의 권한을 가지고 있습니다.

Yana는 모든 실행 환경이 같은 기능을 제공한다고 가정하지 않습니다.

터미널

현재 변경 기능의 승인 후 계속 실행을 지원하는 유일한 채팅 경로입니다.

대화형 실행 승인 후 계속 실행 상태를 변경하는 기능

Studio + 배포된 웹

헤드리스 stdin/NDJSON 계약을 사용합니다. 현재 헤드리스 모드는 상태를 변경하는 기능을 제공하지 않습니다.

형식이 정의된 턴 로컬 프로세스 헤드리스 모드에서 변경 기능 없음

MCP + 어댑터

MCP는 선택 사항이며 스스로 승인을 부여하지 않습니다. 실행 환경별 어댑터의 지원 수준도 서로 다릅니다.

MCP 실험 단계 승인 외부에서 부여 어댑터 지원 수준 차이
