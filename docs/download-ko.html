터미널 도구

명령줄 도구는 별도로 설치합니다.

두 명령줄 도구는 Yana AI 프로젝트에 속합니다. 데스크톱 설치 파일을 대체하지 않으며 Studio를 설치하지 않아도 독립적으로 사용할 수 있습니다.

Yana 프레임워크 · PyPI저장소를 위한 거버넌스, 에이전트, 스킬과 메모리.pip install yana-aiYana Runtime · crates.io표준 Rust TurnEngine과 CLI.cargo install yana-rt

PIP · 저장소 거버넌스

yana-ai — 프로젝트에 거버넌스 계층 적용

Python CLI yana-ai를 설치합니다. 규칙, 훅, 에이전트, 스킬과 명령을 특정 프로젝트에 연결하고 무결성을 확인합니다. 해당 프로젝트 범위에만 적용됩니다.

pip install yana-ai cd your-project yana-ai install # 훅 연결, 약 60초 yana-ai doctor . # 무결성 검사

yana-ai install을 실행하면 AI 에이전트 (Claude Code, Cursor, Codex, Antigravity 등)의 위험한 명령을 감지합니다. Claude Code/Cursor에서는 차단하고 Codex/Antigravity에서는 경고합니다. LLM 호출 없이 로컬에서 기록합니다.

CARGO · 런타임 및 작업 조정

yana-rt — 표준 TurnEngine과 터미널 워크스페이스

Rust CLI yana-rt 를 설치합니다. Yana Studio 내부에서도 같은 바이너리를 사용합니다. 로컬 모델용 터미널 워크스페이스이자 증거, 기능과 메모리에 직접 접근하는 작업 조정 도구이며 Studio 창이 없어도 사용할 수 있습니다.

cargo install yana-rt yana-ai-rt --provider ollama # 터미널 워크스페이스, 로컬 모델 yana-rt route classify "fix auth" yana-rt mission create "add-auth"

터미널 워크스페이스는 스트리밍, 실행 중 취소, 여러 탭과 세션, 실행 중 모델 전환을 지원합니다. route/mission 명령으로 Studio와 같은 런타임에서 의존성을 고려한 작업을 분류하고 생성합니다.

설치 가이드

Studio 1.5 설치 파일을 내려받은 뒤.

Yana Studio는 아직 유료 코드 서명 인증서를 사용하지 않습니다. macOS 빌드는 Apple의 공증을 받지 않았으며 Windows 설치 파일에도 코드 서명이 없습니다. 따라서 처음 실행할 때 Gatekeeper나 SmartScreen 경고가 표시될 수 있습니다. 경고만으로 앱의 고장이나 위험 여부를 판단할 수는 없으며, 이 빌드가 Apple 또는 Microsoft의 검토를 받았다는 뜻도 아닙니다.

경고가 표시되는 이유

코드 서명과 공증은 다릅니다.

Gatekeeper는 신뢰할 수 있는 Developer ID 서명과 Apple의 공증 여부를 확인합니다. 공증에는 자동 악성코드 검사가 포함됩니다. Yana Studio는 임시 서명 (ad-hoc)이 있지만 공증을 받지 않아 경고나 실행 차단이 표시될 수 있습니다.

방법 1 · 권장

오른쪽 클릭 → 열기

  1. 설치 파일 .dmg 를 열고 Yana Studio 를 응용 프로그램폴더로 드래그하세요.
  2. 이어서 응용 프로그램폴더에서 오른쪽 클릭 또는 Control 키를 누른 채 클릭으로 Yana Studio 의 메뉴를 연 뒤 열기 를 선택하세요. 처음부터 두 번 클릭하지 마세요.
  3. 개발자를 확인할 수 없다는 대화 상자가 표시되면 열기 를 선택하세요.
  4. 허용한 뒤 앱을 실행할 수 있습니다. macOS가 선택을 기억하므로 다음부터 두 번 클릭해 열 수 있습니다.

방법 2 · 이미 차단된 경우

시스템 설정 → 개인정보 보호 및 보안

앱을 두 번 클릭한 뒤 Apple이 악성 소프트웨어를 확인할 수 없거나 개발자를 확인할 수 없다는 메시지로 차단되었다면 이 방법을 사용하세요.

  1. 먼저 시스템 설정 → 개인정보 보호 및 보안을 여세요.
  2. 아래로 스크롤해 보안 영역에서 Yana Studio 실행이 차단되었다는 항목을 찾으세요.
  3. 그다음 확인 없이 열기를 선택하세요.
  4. Touch ID나 비밀번호로 확인을 요청하면 인증하세요.
  5. 그런 다음 Yana Studio 를 다시 여세요.

불필요한 보호 기능 해제

Gatekeeper 전체를 끌 필요는 없습니다.

일부 안내는 Gatekeeper 전체 비활성화 (sudo spctl --master-disable)나 터미널에서 격리 속성 제거 (xattr -cr)를 권하기도 합니다. 이 방법들은 사용하지 마세요. 특히 Gatekeeper 전체 비활성화는 모든 앱 에 대한 보호를 약화시킵니다. 위의 방법 1과 2는 해당 앱에만 적용되며, 이 설치를 위해 보호 기능 전체를 해제할 필요는 없습니다.

임시 서명 (AD-HOC)의 의미

서명은 있지만 Developer ID 인증서는 없습니다.

임시 서명은 등록된 개발자 신원 없이 앱 코드를 암호학적으로 봉인하는 방식입니다. macOS가 빌드 이후 파일의 손상이나 변조를 확인할 수 있게 합니다. 서명이 없는 상태와는 다르지만 Apple Developer ID 인증서가 제공하는 신뢰는 없습니다. Apple이 문서화한 서명 방식 (codesign --sign -)을 Apple Silicon에서 앱을 실행하기 위해 사용한 것이며 Apple의 검토나 보증을 뜻하지 않습니다.

WINDOWS

Windows SmartScreen에도 경고가 표시될 수 있습니다.

Windows 설치 파일 (.exe)은 현재 코드 서명이 없습니다 . 프로젝트는 아직 유료 코드 서명 인증서를 사용하지 않습니다. 처음 .exe파일을 실행하면 “Windows의 PC 보호”가 표시될 수 있습니다. 추가 정보 → 실행 을 선택해 진행할 수 있습니다. 서명되지 않은 앱에 표시되는 경고이며, 이 경고만으로 앱의 고장이나 안전 여부를 판단할 수는 없습니다.

LINUX

AppImage는 먼저 실행 권한을 부여합니다.

파일 형식이 .AppImage라면 실행 권한을 주고 직접 실행하세요: chmod +x Yana-Studio-*.AppImage && ./Yana-Studio-*.AppImage. .deb패키지는 sudo dpkg -i Yana-Studio-*.deb명령으로 설치하거나 배포판의 패키지 관리자로 열 수 있습니다. Linux에도 공식 릴리스에서 내려받고 체크섬을 확인한다는 원칙은 같습니다.

다운로드 검증

체크섬을 확인하세요

릴리스에는 설치 파일의 SHA-256 체크섬이 게시됩니다. 다운로드한 파일이 전송 중 손상되거나 변조되지 않았는지 확인하려면 터미널에서 다음 명령을 실행하세요:

shasum -a 256 ~/Downloads/Yana-Studio-*

출력된 값은 릴리스 페이지에 게시된 체크섬과 비교하세요. 이는 공개된 파일과의 일치 여부를 확인하는 무결성 검사이며 코드 서명이나 공증을 대신하지 않습니다.

향후 macOS의 Developer ID 서명과 공증, Windows의 Authenticode 서명이 적용되면 경고와 설치 절차가 달라질 수 있습니다. 그때 이 안내도 업데이트합니다. 자세한 내용은 GitHub의 macOS 설치 안내에서 확인하세요.
