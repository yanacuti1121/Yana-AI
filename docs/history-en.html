Yana has grown
through real incidents.

Failed releases, regressions, packaging bugs, CI failures and redesigns all leave traces in Git history. This page explains what happened, the root cause, the fix and what changed afterward.

Engineering credibility comes from transparency, not from never making a mistake.

INCIDENT 1 — 08–11 Jul 2026

CLI wrapper recursed indefinitely through PATH.

What happenedThe CLI wrapper (scripts/yana-rt-wrapper.js) resolved yana-rt through PATH, which pointed back to the wrapper. This caused infinite recursion, 100% CPU usage and a reported temperature of 116°C before a forced shutdown (55baba91, Jul 8; 727f6623, 22e93c5f, Jul 9).
Root causeThere was no recursion guard when resolving the target binary; the wrapper trusted PATH unconditionally.
FixAn environment flag now guards recursion before exec, preventing the wrapper from calling itself.
System changeRule 71-entry-point-verify-law.md was added (6792487a, Jul 10): every entry point, including CLI wrappers and binaries, must be verified by real exec(), not only by reading the diff. A gap in that rule was fixed the next day (a751af06, Jul 11). Safety rules also need independent review.

INCIDENT 2 — 01 Sep 2026

Desktop v1.4.4 shipped broken.

What happenedv1.4.4 was released (e3a18505) with a packaged server missing all of node_modules, so the downloaded app could not run. This was discovered by launching the actual download from a terminal, despite a green CI run.
Root causePackaging did not copy the child server dependencies into the final artifact. CI checked that the build succeeded, but not that the packaged app launched.
Fixv1.4.5 (b6d65cae) was the first fix but was insufficient. v1.4.6 (afbdc50d) finally packaged node_modules correctly. Three versions shipped in one day.
System changeThe direct lesson became a rule: a green CI result proves little without launching the actual build. The same lesson informed Yana Studio’s packaging pipeline two weeks later.

INCIDENT 3 — 09–11 Sep 2026

macOS reported “Yana Studio is damaged”.

What happenedYana Studio’s first packaging pipeline (9aadc491, Sep 9) used identity: null in electron-builder and skipped signing. macOS Gatekeeper reported the downloaded app as “damaged” when opened.
Root causeThe Electron skeleton already had an ad-hoc signature. After extraResources were added, that signature no longer matched the bundle; codesign --verify --deep --strict reported “code has no resources but signature indicates they must be present”.
FixAn afterSign hook (scripts/after-sign-mac.cjs) now signs the complete bundle after packaging (dd427d54, Sep 11) instead of relying on the skeleton’s signature.
System changeThe download page now includes full Gatekeeper guidance and inline steps per operating system rather than a one-line warning.

INCIDENT 4 — 11 Sep 2026

A correct fix still triggered supervisor HALT.

What happenedThe circuit breaker’s half-open reset bug (src/guard/token_budget.rs) was fixed correctly (e39a9c4d), but the hash pins in core-lock.json were not updated at the same time.
Root causeFiles in core/rules/, core/hooks/, core/gates/ and core/scripts/ are pinned with SHA-256. Changing one without running update-core-lock.sh causes a hash mismatch. The supervisor behaved as designed.
FixThe manifest was regenerated with update-core-lock.sh and committed alongside the original fix (605d9aff, #339).
System changeThis is the intended behavior: a valid change missing a synchronization step is blocked automatically instead of slipping through. Fail closed, not open.
