01 — 실행의 경계

제안은 실행이 아닙니다.

모델이 제안을 만들면 Yana가 권한을 확인합니다. 허용된 범위의 기능만 적절한 실행 경로에서 사용하고 결과를 증거 기록으로 남깁니다. 정책상 필요하면 사람이 승인합니다.

지능

모델에 종속되지 않음

클라우드나 로컬 모델을 바꿔도 시스템의 권한 경계는 그대로 유지됩니다.

권한

사람이 통제함

최종 결정권을 모델의 추론 능력과 혼동하지 않습니다.

증거

확인 가능

모든 행동은 결정, 허용된 기능, 확인 가능한 증거 기록과 연결됩니다.

02 · 한 번의 작업 흐름

네 단계 모두 모델 밖에서 이루어집니다.

모델은 파일을 쓰거나 명령을 실행하는 등의 행동을 제안할 뿐입니다. 제안 자체는 아무것도 바꾸지 않습니다. YanaAuthorityChain이 먼저 허용, 사람에게 승인 요청, 거부 중 하나를 결정합니다.

허용된 기능만 부여된 범위 안에서 실행됩니다. 결과는 실행을 허용한 결정과 연결된 증거 기록이 됩니다. Studio와 Runtime CLI도 같은 경로를 따릅니다.

제안과 실행 사이에 모호한 단계는 없습니다.

모델이 제안제안
권한 체인이 결정허용 · 승인 요청 · 거부
허용 범위에서 기능 실행실행
결과 기록증거 기록

03 · 시스템 내부

여섯 계층, 각자의 역할.

Yana는 지능, 권한, 실행, 증거를 명확한 계약으로 연결된 독립 계층으로 나눕니다. 한 계층을 바꿔도 다른 계층의 경계까지 바꿀 필요가 없습니다.

사용자 인터페이스

사람이 일하는 곳

Studio, Terminal, Web, Discord는 사용자 인터페이스입니다. Studio와 Runtime CLI는 같은 제어 계층을 사용합니다.

감독자

AI 세션 밖의 감시

감독자는 운영체제 계층에서 독립적으로 실행됩니다. 승인되지 않은 변경을 감지하면 세션 전체를 HALT할 수 있습니다. Claude, Codex, Cursor의 훅은 HALT를 따르며 스스로 그 권한을 얻지 않습니다.

제어 계층

정책, 작업, 기억

정책, 신원, 기능, 증거가 이 계층에 있습니다. 작업 그래프, 미션, L1/L2 기억, 프로젝트 기억은 한 번의 대화가 끝나도 작업을 이어 줍니다.

RUST TURNENGINE

형식이 정의되고 취소할 수 있는 작업 턴

yana-rt는 형식이 정의된 턴, 스트리밍, 실행 중 취소, 도구 호출 루프를 처리합니다. Studio는 별도 구현 대신 CLI와 같은 yana-rt 바이너리를 실행합니다.

모델 + 허용된 기능

지능과 범위가 정해진 도구

로컬 및 클라우드 제공자는 하나의 권한 모델을 사용합니다. 기능은 접근(파일 읽기와 Git 검사), 변경(파일 쓰기, 설정, 커밋), 실행(셸 명령, 프로세스, 시스템 작업)으로 나뉩니다.

증거

증거 기록과 감사 추적

각 도구 호출은 해시로 연결된 감사 기록에 포함됩니다. 실행 결과에는 Truth Gate를 통한 HMAC 서명이 붙습니다. 기록을 수정하면 감지 가능한 흔적이 남습니다.

04 · 권한이 곧 아키텍처

범위와 기간이 정해지고 취소할 수 있습니다.

정책은 모델 밖에 있습니다. 긴급 중지에도 절차가 있습니다. HALT를 해제하려면 담당자와 이유를 먼저 기록해야 하며 어떤 에이전트도 스스로 잠금을 풀 수 없습니다.

기능 명세

모든 행동에는 공식 이름이 있습니다

각 행동에는 위험 수준과 승인 규칙이 있습니다. 예를 들어 file.write는 상태를 바꾸므로 승인이 필요합니다.

범위가 정해진 권한 부여

주체, 범위, 시간에 따른 권한

권한은 지정된 세션과 디렉터리에 제한된 시간 동안 적용되며 언제든 취소할 수 있습니다.

오류를 명확하게 표시

권한 검사가 빠지면 드러나야 합니다

Yana는 권한 검사를 조용히 건너뛰지 않습니다. 거부는 명시적으로 표시되며 HALT가 항상 최우선입니다.

05 · 모델 독립성

모델은 바꿔도 규칙은 유지합니다.

Yana는 Anthropic, OpenAI, Gemini, Groq, DeepSeek, OpenRouter와 로컬 Ollama를 지원합니다. 제공자를 선택하면 Yana가 기본 모델을 고르므로 목록을 직접 찾아볼 필요가 없습니다.

모델이 바뀌어도 오른쪽 계층은 그대로 남습니다. 그래서 Yana는 단일 모델을 감싼 도구가 아니라 제어 계층입니다.

지능은 바뀔 수 있어도 권한은 흔들리지 않아야 합니다.

미션변경 없음
작업변경 없음
프로젝트 기억변경 없음
권한 체인변경 없음
증거변경 없음

06 · 현재의 한계

완료되지 않은 작업도 분명히 보여 줍니다.

이 페이지는 근거가 있는 내용만 설명합니다. Yana의 감사 기록은 변조를 감지할 수 있지만 변조 자체를 완전히 막지는 못합니다. 다음 영역은 아직 완성되지 않았습니다.

로드맵

Continuity Engine

작업 그래프, 미션, L1/L2 기억은 작동 중입니다. 완전한 Continuity Engine은 아직 로드맵에 있습니다.

미검증

Wheelbot

Wheelbot에는 별도의 WebSocket/MCP 기기 브리지가 있습니다. 이 경로가 같은 TurnEngine을 통해 처음부터 끝까지 검증되었다고 주장하지 않습니다.

실험 단계

MCP

MCP는 선택 사항이자 실험 단계이며 그 자체로 승인을 부여하지 않습니다.

전체 적용 전

제공자 게이트웨이

새 제공자 게이트웨이는 아직 모든 요청의 처리 경로가 아닙니다.

인터페이스별

승인 후 계속 실행

현재 상태를 바꾸는 기능에 대해 승인 후 계속 실행할 수 있는 경로는 Terminal 채팅뿐입니다. 배포된 Studio와 Web은 헤드리스로 실행되며 아직 변경 기능을 제공하지 않습니다.

적용 강도 차이

외부 어댑터

하네스 어댑터마다 강제 수준이 다릅니다. Yana는 모든 하네스가 똑같이 엄격하다고 가정하지 않습니다.

07 · 터미널 도구

Yana를 쓰는 데 Studio가 꼭 필요한 것은 아닙니다.

Yana AI에는 서로 독립적인 CLI 두 가지가 있습니다. 각각 해당 언어의 표준 패키지 관리자로 설치하며 Yana Studio에는 영향을 주지 않습니다.

PIP · 저장소 관리

yana-ai — 프로젝트에 관리 계층 적용

Python CLI yana-ai를 설치합니다. 이를 통해 규칙, 훅, 에이전트, 스킬, 명령을 특정 프로젝트에 연결하고 무결성을 확인합니다. 모든 것은 해당 프로젝트 범위에만 적용됩니다.

pip install yana-ai cd your-project yana-ai install # 훅 연결, 약 60초 yana-ai doctor . # 무결성 검사

실행 후 yana-ai install, AI 에이전트(Claude Code, Cursor, Codex, Antigravity 등)가 위험한 명령을 시도하면 가로채서 기록합니다. Claude Code/Cursor에서는 차단하고 Codex/Antigravity에서는 경고합니다. 모두 로컬에서 처리하며 LLM 호출은 없습니다.

CARGO · 런타임 및 작업 조정

yana-rt — 표준 TurnEngine과 터미널 워크스페이스

Rust CLI yana-rt를 설치합니다. Yana Studio 내부에서도 같은 바이너리를 실행합니다. 로컬 모델을 위한 터미널 워크스페이스이자 증거, 기능, 기억에 명령줄로 접근하는 작업 조정 도구이며 Studio 창이 없어도 사용할 수 있습니다.

cargo install yana-rt yana-ai-rt --provider ollama # 터미널 워크스페이스, 로컬 모델 yana-rt route classify "fix auth" yana-rt mission create "add-auth"

터미널 워크스페이스는 스트리밍, 실행 중 취소, 여러 탭과 세션, 실행 중 모델 전환을 지원합니다. route/mission Studio와 같은 런타임에서 의존성을 고려해 작업을 분류하고 생성합니다.

08 · 계속 살펴보기

모든 계층이 작동하는 모습을 보고 싶으신가요?

아키텍처 페이지에서는 전체 구조를, 런타임 페이지에서는 한 번의 작업 흐름을, 거버넌스 페이지에서는 권한 유지 방식을 살펴볼 수 있습니다.
