AGENTS & SKILLS

100 agents.
2,026 skills.

Those two numbers don't mean 2,126 processes are running. An agent is a persona dispatched synchronously for one task; a skill is knowledge loaded when its trigger matches. Nothing here is "always on" in the background.

See agentsSee skills

AGENTS

Synchronous dispatch, not a background swarm.

The main agent calls one subagent for one specific task, the subagent returns a text report, the main agent decides the next step. No subagent process exists between dispatches.

Read-only by default

A subagent can't Write/Edit, can't git commit/push, can't run a hook — only the main agent holds that authority.

subagent: read, grep, glob main agent: write, commit, push

A text report, not a diff

A subagent returns findings + evidence + a recommendation in writing. The main agent applies the change itself — it never receives a diff directly from a subagent.

Findings Evidence & Reasoning Recommended actions "No files were modified."

Bounded delegation depth

Root agent → subagent A → subagent B is the maximum. No infinite dispatch chains allowed.

depth 0 → 1 → 2 → 3 (max)

SKILLS

Knowledge loaded on demand,
not an automatic hook.

A skill is a guidance file with a clear purpose, trigger conditions, rules and a verification step. It doesn't run on its own — it's only read when a user's question matches its trigger. The 2,026 skills in this repo cover hundreds of domains, from frontend and security to robotics.

No matchskill has zero effect
Length cap≤ 220 lines / skill
Overlapmerged, not duplicated

EXTERNAL SKILLS

Vetted vendoring, not dumped in.

When bringing in an open-source skill, Yana checks its license first, keeps the original content unmodified, and records the source in an accompanying ATTRIBUTION.md file.

1. Check the license

Only vendor licenses that allow redistribution (MIT, Apache 2.0...). No copying code with an unclear license.

2. Keep the original verbatim

Vendored skill content is unmodified — no silent "improvements" that drift from upstream.

3. Check for trigger overlap

If it overlaps an existing skill's scope, add a "Do NOT use for" cross-reference between the two instead of letting the agent pick at random.
