차단 계층

단일 명령에서 전체 세션까지.

파괴적 명령 차단기

명령 실행 전에 차단: rm -rf, 강제 푸시, 셸로 이어지는 파이프, 테이블 삭제. 실행을 마친 뒤 경고하는 방식이 아닙니다.

rm -rf → 차단 git push -f → 차단 curl | bash → 차단

영향 범위 정책

여러 파일이나 민감한 영역을 다루는 작업은 실행 전에 명시적인 승인이 필요합니다.

명령 하나로 파일 50개 초과 처리 → 명시적인 승인 필요

서킷 브레이커

반복해서 실패하는 도구를 일정 시간 잠급니다 (60초 → 300초 → 1800초). 끝없는 재시도로 토큰이 소모되는 것을 막습니다.

CLOSED → OPEN → HALF_OPEN → CLOSED

감독자 · GIÁM THỊ

AI 세션 밖에서 동작하는 감독자.
세션이 끝나도 계속 작동합니다.

채팅 세션의 훅은 공유된 안전 상태를 따르며 스스로 HALT 권한을 갖지 않습니다. 이 권한은 운영체제 수준에서 독립 실행되는 감독자(Giám Thị)에게 있습니다. 감독자는 주기적으로 상태를 확인하고, 민감한 영역의 검토되지 않은 변경을 감지하면 프로젝트 전체를 잠글 수 있습니다.

주기적 상태 확인CPU, RAM, 디스크, 세션, 실행 기록 체인
이상 징후 감지공유 잠금 파일을 생성합니다
모든 AI 세션즉시 잠금 적용
잠금 해제해제 주체와 이유를 먼저 기록해야 함

인프라 무결성

규칙과 훅도 해시로 무결성을 확인합니다.

core/rules/, core/hooks/, core/gates/ 이 파일들의 SHA-256 해시는 별도 명세에 기록됩니다. 명세를 갱신하지 않고 파일을 바꾸면 감독자가 다음 점검에서 HALT를 실행합니다. 이 프로젝트 개발 중에도 실제로 발생한 일입니다.

감사의 말

Yana AI는 Apache 2.0, MIT 및 기타 허용 라이선스 하에 라이선스된 프로젝트를 포함하여 오픈소스 커뮤니티의 아이디어, 패턴 및 도구를 기반으로 구축되었습니다. 모든 제3자 소스는 각 라이선스에 따라 준수하여 사용됩니다. 이 프로젝트는 개인이나 조직의 지적 재산권을 복사, 오해하거나 침해할 의도가 없습니다. 특정 프로젝트가 디자인 결정에 직접적인 영향을 미친 경우, 관련 소스 파일 및 규칙 문서에 출처가 명시됩니다.
