YANA GOVERNANCE

Intelligence is not authority

A model can propose an action. It cannot grant itself a capability, raise its own autonomy ceiling, manufacture human approval, or disable HALT. This page shows the mechanisms — not a security slogan.

Authority order

Every request passes through this order, top to bottom. No layer can skip the one above it.

  • Giám ThịRoot safety authority. Checks a HALT lock before any provider turn. Its existence means stop — and no layer below, including Yana's own policy, can override it.
  • Yana control planeOwns identity, policy, approval semantics, autonomy, audit, and evidence. Maps a model's proposal to a canonical capability before any permission is evaluated.
  • Capability manifestLookup → availability check → risk/approval policy → Allow, Deny, or Await Human Approval. Awaiting is never silently promoted to Allow.
  • Bounded executionOnly after approval — and re-checked immediately before it runs, in case state changed since the human looked at it.

A file mutation, start to finish

This is the strongest concrete example of what "governed" actually means — real, shipped, tested (see src/capability/file_mutation.rs).

Propose→ Compute diff→ Guard→ Human approval→ Backup→ Atomic write→ Re-verify→ Evidence

Why re-verify matters: the diff a human approved is not assumed valid forever. If another process edits the file between approval and execution, Yana recomputes the diff rather than writing blind — an old approval never authorizes a different change than the one that was shown.

Audit chain

Every allowed and blocked action is logged as a hash-linked JSONL entry. Editing an earlier line breaks recomputation of everything after it.

Precise wording, on purpose: this is tamper-detectable, not tamper-proof. A determined actor with disk access can still delete the log file itself — what the chain guarantees is that a modified entry is mathematically detectable, not that modification is impossible.

Giám Thị · HALT

An independent halt watcher, opt-in at install, running outside any Yana session entirely.

Runs on a real OS scheduler (macOS LaunchAgent / cron) and checks core-lock integrity, audit-chain integrity, and recent changes to security-sensitive paths every few hours. On any finding, it writes a lock file — .claude/state/GIAMTHI_HALT.lock — that makes every subsequent tool call in every session against that repo deny outright. No bypass flag. No code path, in this watcher or any other, that clears it.

The asymmetry is deliberate: the thing that can stop a session isn't the thing that can restart it. Only a human, after reading the lock's reason and deleting the file by hand, can resume — so a compromised or simply wrong agent can't grade its own homework and wave itself back in.
